## 三、论文术语 ↔ 代码对照表

读论文时最卡的地方，往往是「这一句落到代码是哪一行」。直接查表：

| 论文里的说法 | 代码里是什么 | 在哪 |
|---|---|---|
| Scaled Dot-Product Attention | `att = q @ k.T / sqrt(d_head)`，再 softmax | step0 第 3~5 步 |
| 为什么要除 sqrt(d_k) | 点积方差正比于维度，不缩放 softmax 会饱和 | step0 第 3 步注释 |
| Multi-Head Attention | `MultiHeadAttention` 类 | step0 第 8 步 |
| Position-wise Feed-Forward | `FeedForward` 类（两层线性 + 激活） | step1 |
| Add & Norm | `x = x + self.attn(self.ln1(x))` | step1 `Block` |
| Positional Encoding | `nn.Embedding(block_size, n_embd)` | step1 / step3 |
| Encoder（双向注意力） | `EncoderLayer`，`causal=False` | step2 |
| Decoder | `DecoderLayer` = 自注意力 + cross-attn + FFN | step2 |
| Masked Multi-Head Attention | 同一个类，传 `causal=True` | step2 |
| Cross-Attention | 同一个类，传 `memory=encoder输出` | step2 |
| Weight Tying | `self.lm_head.weight = self.tok_emb.weight` | step1 / step3 |
| Learning Rate Warmup | `get_lr()` | step1 / step3 |
| Dropout（3.4 节） | `nn.Dropout`，p=0.1 | 各处 |
| Label Smoothing（5.4 节） | **没实现**，小模型上收益不明显 | —— |

**三种注意力在代码里是同一个类**，只差两个开关：

```
                       memory         causal
encoder 自注意力        None           False    ← 双向，能看全句
decoder 自注意力        None           True     ← 不能看未来
cross-attention        encoder 输出    False    ← Q 来自 decoder，K/V 来自 encoder
```

论文 Figure 1 里画成三种不同样子的箭头，落地就这一个类。

## 四、五个阶段分别在讲什么

### 阶段 0：注意力（唯一需要动脑的地方）

输入 `(B, T, d)`，输出 `(B, T, d)`——**形状不变**。记住这一点，后面所有结构就都顺了：
能堆 N 层，就是因为进出口形状一样。

核心只有一行：`q @ k.T` 得到 `(B, head, T, T)`。
那个 T×T 矩阵，第 i 行第 j 列 = 「位置 i 有多想关注位置 j」。

**这个 T×T 就是 O(T²) 的唯一来源。** 序列翻倍、计算翻四倍。
KV cache、FlashAttention、长上下文为什么贵，根全在这。

### 阶段 1：自监督目标（论文完全没讲的部分）

论文做机器翻译，输入输出都是现成的句子对。GPT 换了个做法：

```python
x = data[i     : i + block_size    ]   # 模型看到的
y = data[i + 1 : i + block_size + 1]   # 模型要预测的（右移一格）
```

就这一格偏移，语料自动变成几十万条训练样本，不需要任何人工标注。
**这是 GPT 路线里最优雅的一步。**

### 阶段 2：补齐论文左半边

前期只用了 decoder。这里加上 encoder、cross-attention、以及论文原版的正弦位置编码。

任务换成「把数字序列倒过来」，因为它有唯一正确答案，能用**准确率**而不是 loss 来判断。
这是「真懂没真懂」的检验方式——loss 从 2.5 降到 2.3 看不出发生了什么，
准确率 3% 涨到 98% 没有任何歧义。

### 阶段 3：真实工程

换真分词器、换中文语料、上混合精度和梯度累积。这一步跑完，
就有一套和工业界同构（只是小很多）的预训练流程了。

### 阶段 4：评估（比训练更容易出错的一步）

训练只有一种失败方式——loss 不降。评估有一百种失败方式，而且每种都
**看起来像成功**：perplexity 跨分词器比错了、拿单一指标选配置、把测试集调脏了。
这个阶段教的是「怎么不被自己的数字骗」，详见第九节。

## 五、几个必须搞懂的机制

### 位置编码：注意力天生不认识顺序

注意力算的是「任意两个位置的内积」，把输入序列打乱，输出只是跟着换个顺序，
信息量一模一样。但语言有顺序（「狗咬人」≠「人咬狗」），所以必须额外把位置喂进去。

两个实现都试过了，直接给结论：**外推能力没差别**（详见第六节）。

### 因果 mask：GPT 的核心机制

位置 t 只能看到 0..t。做法是把右上角设成 `-inf`，softmax 之后自动变 0。

没有它，模型训练时能看到答案，loss 会漂亮得不像话，但推理时完全不能用。
**训练时能偷看答案，是新手最常犯的错之一。**

### 残差：为什么 `x = x + f(x)`

求导时那个 1 保证梯度原样传回去，不会每过一层衰减一次。
没有残差，6 层就够呛，更别说几十上百层。

### pre-norm vs post-norm：唯一故意偏离论文的地方

```
论文（post-norm）：x = LayerNorm(x + Sublayer(x))
这里（pre-norm） ：x = x + Sublayer(LayerNorm(x))
```

论文放后面，现代实现放前面。原因：post-norm 在层数多时训练不稳定，
要精细调 warmup 才能收敛；pre-norm 让残差通路变成一条梯度「高速公路」。
翻任何开源大模型的代码，看到的都是 pre-norm。

### 梯度累积：小显存训大模型的标准手段

```python
有效批大小 = micro_batch × grad_accum × block_size
            = 8 × 4 × 512 = 16384 个 token
```

显存只装得下 8 条样本的中间激活值，但希望一次更新看到更多样本。
办法是攒 4 次梯度再更新一次——数学上等价于 batch=32，显存开销只有 8 的。

**注意那个 `loss / grad_accum`，少了它梯度会放大 4 倍，训练直接发散。**

### 混合精度 bf16

前向反向用 16 位算，权重更新仍是 32 位。显存和带宽约减半。
为什么用 bf16 不用 fp16：bf16 的动态范围和 fp32 一样，不像 fp16 那样容易溢出。

## 六、实测结论（可直接引用，省去重复实验）

以下都是在本机上真跑出来的：

**1. 正弦位置编码没有带来外推优势。**
同样 3000 步、同样任务，训练长度 1~8：

| 测试长度 | 可学习 embedding | 论文的 sin/cos |
|---|---|---|
| 4、8（训练内） | 100% | 100% |
| 10（训练外） | 79.9% | 79.9% |
| 12（训练外） | 66.5% | 66.5% |

**完全一样。** 位置向量能靠公式算出来 ≠ 模型会用——注意力模式是训练出来的，
只见过长度 ≤8 的交互，长了照样崩。次要差异：正弦编码收敛更慢
（500~1000 步卡在 26.7%，可学习编码 500 步就到 84.8%）。

**2. padding 结构是输入分布的一部分，训练和推理必须一致。**
详见第七节第 1 条，这是整个实验里最有价值的一个坑。

**3. 词表裁剪的收益大得离谱。**
繁体古籍语料下，cl100k_base 的 100277 个词条只用到 **1066 个（1.1%）**——
因为它的中文词条几乎都是现代简体词，古汉语用字基本不在里面，
分词器退化成字节级（1 个汉字 ≈ 1.5 个 token）。

裁剪后输出层参数 38.5M → 0.41M，模型 49.3M → 11.2M，训练快好几倍，**表达能力无损**。

**4. 小模型的真实能力边界。**
2.73M 参数的字符级 GPT 训 2000 步（181 秒），能学会莎剧的版面结构
（`FRIAR LAURENCE:` 这种全大写角色名 + 冒号 + 换行完全正确）和词汇分布，
但不懂语义，温度调到 1.0 拼写就开始崩。**它学到了语言的形式，没学到意义。**

**5. 显存根本不是瓶颈。**
2.73M 模型 fp32 权重只有 10.9MB；11.2M 模型训练峰值显存 1.3GB。12GB 很宽裕。

**6. 11.2M 中文模型训 3000 步后的客观读数：**
测试段 loss 2.68，**BPC 5.68 比特/字符**，比「只按字频猜」的基线好 **52.4%**，
train/test 差距 +0.21（未过拟合），推荐采样 温度 0.7 / top-k 50。详见第九节。

**7. 两个单指标都能被「退化的输出」骗到，而且方向相反。**
- 「3字组命中率」会被**复读**刷虚高：复读的文本 n-gram 高度重复，
  重复的 n-gram 恰好都在语料里。实测 0.5/top-k 1000 命中 0.901 全场第一，
  实际在句式级打转（「那人道：『你們是那裏來的？』」循环）。
- 「distinct-2」会被**乱码**刷虚高：温度越高越不重复。实测 1.1/top-k 200
  distinct-2 0.970 全场第一，命中只有 0.441，已经不成词。

**结论：选采样配置必须用「一个可跨温度比的决策指标 + 一个硬约束」，缺一个就会选错。**
（这两条是本实验里除了 padding 那个坑之外最有价值的发现。）

**8. 采样指标的方差差别巨大。** 同一配置重跑：distinct-2 稳定在 ±0.02 内，
但「最长复读」（12 条样本取最大值）能从 1.7 跳到 8.2。**能看均值就别只看极值。**

## 七、踩坑清单

### 1. 缓冲区长度必须固定（最容易中招）

第一版让张量长度 = 当前任务的最大长度，结果出现了一个极隐蔽的问题：

```
序列长度 4  -> 整句准确率 49%     <- 反常！应该比长度 8 简单
序列长度 8  -> 整句准确率 100%
```

原因：同一句「长度 4」的样本，训练时后面跟着 4 个 `PAD`，**评估时一个 PAD 都没有**。
encoder 是双向注意力，它会真的「看到」那些 PAD 位置，
attention 的 softmax 要在更多/更少的元素上归一化，输出的表示就飘了。

而长度 8 因为两次都恰好「无 PAD」，侥幸 100%——**这种「部分正确」最容易骗过自己。**

**修法**：定义 `BUF = 12` 常驻，训练、评估、生成共用同一个张量长度。

> 这就是论文里一句 "we pad sequences" 背后真正要处理的东西。论文一个字没写。

### 2. teacher forcing 和自回归必须分开评估

- `evaluate()` 喂正确答案（teacher forcing）→ 测的是「每一步会不会」
- `greedy_decode()` 把自己的输出接回去 → 测的是「整条能不能生成对」

两者结果可以差到 **100% vs 0%**，这是 exposure bias，不是 bug。
排查顺序：先查上面的 padding 一致性，再怀疑 exposure bias。

### 3. 提示词的字形必须和语料一致

语料是**繁体**古籍，提示词写成简体「却说」会直接报错——「却」这个字从没在语料里出现过，
编码出来是词表外的 id，拿去索引 embedding 就越界了。繁体写法是「卻說」。

**词表裁剪之后这个坑更容易踩**：模型只认语料里出现过的 token，
任何语料外的用字都无处安放。写提示词前先确认字形。

### 4. 训练一结束就先存盘

第一版把「生成演示」放在「保存权重」**之前**，结果提示词写错字形抛了异常，
七分钟训出来的权重跟着一起没了，只能重跑一遍。

**演示环节永远放在落盘之后。** 训练的成果比演示重要得多。

### 5. 其它

- `ignore_index=PAD`，否则模型会花容量去学「预测填充符」
- 评估时要 `model.eval()`，否则 dropout 让数字抖动；用完恢复
- 训练脚本开头要 `sys.stdout.reconfigure(encoding="utf-8")`，否则 Windows 控制台中文炸
- 权重初始化用 `std=0.02`，别用默认的 `1/sqrt(fan_in)`，否则 logits 一开始就太大

## 八、怎么读 loss 和 perplexity

```
loss 4.2043   ← 随机猜的水平是 ln(词表大小)
```

阶段 1（词表 65）：`ln(65) = 4.17`，训练后降到 **1.49**
阶段 3（词表 1066）：`ln(1066) = 6.97`，训练后降到 **2.68**

**perplexity = exp(loss)**，含义是「模型在每个位置的不确定程度，相当于在多少个候选里猜」。
阶段 1 从 66.96 降到 4.41 —— 等于从「65 个字里瞎猜」变成「大概 4~5 个字里挑」。

> **但这两个 perplexity 不能互相比较**（4.41 vs 14.61 不代表阶段 1 更好）。
> 分母不一样。要跨分词器比，用 BPC。理由见第九节第一层。

**train 和 val 两条线的关系比绝对值更重要**：
- 两条一起降 → 正常学习
- val 开始回升而 train 继续降 → 已经开始背训练数据，该停了

实测这个模型到 3000 步两条都在降、差距稳定在 +0.21，属于「还能再训」的状态。

## 九、怎么测一个训好的模型

「测试」不是一件事，是三个层次。混在一起谈，就退化成「感觉生成的还挺像」。

```
第一层 · 看数      loss / perplexity / BPC     客观、可比较、能画曲线
第二层 · 看基线    比「瞎猜」「只按词频猜」好多少    回答「到底学到东西没有」
第三层 · 看输出    生成质量的客观量化            数出重复率，不凭感觉
```

顺序不能颠倒：先看数排除明显问题，再看基线确认不是幻觉，最后才花时间品生成质量。
`step4_evaluate.py` 三层都覆盖，下面的数字都是它跑出来的。

### 第一层：唯一能跨分词器比较的指标是 BPC

会得到这样一组数字，看起来互相矛盾：

| | 词表 | val loss | perplexity |
|---|---|---|---|
| 阶段 1（字符级） | 65 | 1.49 | **4.41** |
| 阶段 3（BPE） | 1066 | 2.68 | **14.61** |

看起来阶段 1 好得多？**完全错误，这两个数不能比。**

```
perplexity = exp(平均每个 token 的交叉熵)
```

「每个 token」是多少内容，取决于分词器。阶段 1 一个 token = 一个字符，
阶段 3 一个 token = 0.68 个字符。**切得越碎，同样的内容用越多 token 表示，
perplexity 天然越大。** 这不是模型变差了，是尺子换了。

能比的只有 **BPC（bits per character）**：

```
BPC = loss / ln(2) / (平均每个 token 覆盖几个字符)
```

它的含义是「编码一个字符需要多少比特」，和词表大小、分词方式都无关。
阶段 3 实测 **BPC = 5.68 比特/字符**。换分词器、换结构时，拿 BPC 比。

顺带一个读数：**train 和 test 的 loss 差距**就是过拟合的读数。
实测 +0.21（train 2.47 / test 2.68），而两条曲线都没抬头——
说明这个模型**还没开始背训练数据，继续训还有余量**。

### 第二层：不比基线，就不知道模型是不是在装样子

光看 loss 2.68 是没有意义的，得有参照物：

| 方案 | 测试段 loss | BPC | 相对「均匀瞎猜」的改进 |
|---|---|---|---|
| 均匀瞎猜（什么都不学） | 6.97 | 14.78 | 0.0% |
| 只按字频猜（一元模型） | 5.63 | 11.94 | 19.2% |
| **本实验模型** | **2.68** | **5.68** | **61.5%** |

这张表回答的是「模型到底学到东西没有」，读法是把它拆成两段：

- 瞎猜 → 只知字频，干掉了 **19.2%**。这一段几乎不需要任何「智能」，
  统计一下词频就行。**如果模型连这 19.2% 都没拿到，说明它啥也没学到。**
- 字频 → 本实验模型，又干掉 **52.4%**。这一段靠的是上下文——
  **也就是注意力真正在做的事。**

> 一元模型基线是评估里最容易被跳过、但最有价值的一步。
> 它便宜到可以随手算，却能把「模型学会了」和「模型只是记住了字频」分开。

### 第三层：把「生成得好不好」变成数字

肉眼读几段是发现不了复读的，必须量。脚本扫一个 `温度 × top-k` 网格，
每格采 12 条 150 字，算四个指标。关键是要有一条**参考线**——
真实语料自己也过一遍同样的指标，否则数字没有意义：

| 配置 | 3字组命中 | distinct-2 | 最长复读 | 语料外字 |
|---|---|---|---|---|
| **真实语料（人写的）** | 1.000 | **0.923** | 2.2 | 0.0 |
| 0.5 / 1000 | **0.901** | 0.679 | 2.2 | 0.0 |
| **0.7 / 50（推荐）** | 0.804 | 0.870 | 1.8 | 0.1 |
| 1.1 / 200 | 0.441 | **0.970** | 1.7 | 0.4 |

**这四个指标是两个方向，不是一件事：**

- **3字组命中**：生成的三字组有多少在真实语料里出现过。衡量「像不像中文」。
  对温度不敏感，所以可以跨温度比。
- **distinct-2**：不重复的二字组合占比。衡量「多不多样」。人写的是 0.923。
  但它**不能跨温度比**——温度越高随机性越大、重复天然越少。
- **最长复读**：连续相同字符的最大长度，复读机的直接读数。正常中文 ≤ 3。
- **语料外字**：生成了多少语料里没有的字符。主要是 `�`——
  字节级分词里半个汉字的片段没接上，见第七节第 3 条。

### 【本节最关键的地方】单一指标一定会骗人

看上面那张表的第一名和第二名，**它们都是坏答案，只是坏的方向相反**：

- **命中率最高的 0.5/1000（命中 0.901，全场第一）在复读。**
  采出来是这样的：
  ```
  那人道：「我們是那裏來的？」那人道：「你們也不是那裏來的？」
  那人道：「我們是東土大唐朝來的。」那人道：「我們且住……
  ```
  复读的文本三字组高度重复，而重复的三字组恰好都被语料覆盖，
  于是命中率被刷得虚高。**命中率会被复读骗到。**
  （注意它的「最长复读」只有 2.2——字符级没重复，是**句式级**在打转。
   只有 distinct-2 抓得住它。）

- **distinct-2 最高的 1.1/200（0.970，全场第一）已经不成词了。**
  用高温度把重复率刷下去，得到的是更乱的文本。**distinct-2 会被乱码骗到。**

所以正确做法是**一个决策指标 + 一个硬约束**，缺一个就会选错：

```
决策：用 3字组命中  →  因为它可跨温度比
约束：distinct-2 不能低于真实语料的 85%（= 0.784）  →  因为不许复读
```

门槛也不拍脑袋——直接按真实语料打折自动算出来：

```python
bar_d2 = 0.85 * ref_rep["d2"]      # 参考线 0.923 → 门槛 0.784
pool = [配置 for 配置 in 网格 if d2 >= bar_d2 and 最长复读 <= 3]
推荐 = max(pool, key=命中率)
```

实测这套规则选出 **0.7 / top-k 50**，命中 0.804 / distinct-2 0.870，采出来是：

```
卻說道：“大夫來了，你可巧討這些人來？"薛姨媽道：“這是怎么樣的．
你就說他為著呢。”寶玉道：“他那時常常見他們想的，還敢叫他呢．
```

### 三条关于评估本身的实话

1. **采样类指标有方差，极值类指标方差特别大。** 同一配置跑三次，
   distinct-2 稳定在 ±0.02 内，但「最长复读」能从 1.7 跳到 8.2——
   它是 12 条样本取一次最大值，一条坏样本就把它带飞。
   **能算均值就别只看极值，能多采几条就别只采一条。**
2. **`0.9 / 200` 那一格两次跑出「最长复读 8.2」，横竖都不该用。**
   这类格子是靠约束项剔除的，不是靠肉眼——所以约束项不能省。
3. **测试集可能已经不干净了。** 这个模型训练用随机窗口采样，
   整个语料都被反复看过，严格意义上唯一没参与过梯度的只有最后 2%。
   而且如果拿这 2% 去挑超参数，它**就不再是测试集了**。
   评估里最容易自欺的一步就是反复用同一个测试集调参。

### 生成是最贵的一步，所以要缓存

每格 12 条 × 150 字，而脚本**没有 KV cache**——每吐一个字都要把整条前缀
重算一遍。跑满整个网格要 **13 分钟**。所以结果会存到
`out/eval_grid_gpt_zh1.json`，改分析、改输出格式时加 `--reuse` 直接读：

```bash
python step4_evaluate.py --ckpt out/gpt_zh1.pt --reuse   # 7 秒
```

> 这也顺手回答了「KV cache 值不值得做」：现在生成 150 字要做 150 次前向，
> 有了 cache 之后每次只算 1 个位置。**这就是它在大模型推理里是标配的原因。**

## 十、可以自己动手做的实验

改参数重跑，用 `--tag` 区分输出，然后对比 `out/loss_*.csv`：

```bash
# 更深的模型
python step3_bpe_gpt.py --n-layer 10 --tag deep

# 上下文减半，训练更快
python step3_bpe_gpt.py --block-size 256 --tag short

# 显存不够时：micro-batch 减半，grad-accum 加倍（有效批大小不变）
python step3_bpe_gpt.py --micro-batch 4 --grad-accum 8 --tag small

# 训更久，观察 val loss 什么时候开始回升
python step3_bpe_gpt.py --max-iters 6000 --tag long
```

**五个值得亲手验证的问题：**

1. **block_size 从 256 加到 512，loss 能多降多少？** 这就是「上下文窗口值不值得」的直接答案。
2. **把 `causal=True` 改成 `False` 会怎样？** 训练 loss 会掉得飞快，但生成出来全是垃圾
   —— 亲眼看见「偷看答案」的后果，比读十遍解释都管用。
3. **把某个 Block 的残差去掉会怎样？** 训练会明显变难。这是残差作用最直观的证明。
4. **用单一指标选采样配置，亲眼看它选错。** 生成结果已经缓存在
   `out/eval_grid_gpt_zh1.json`，7 秒就能重跑一遍分析：
   - 把 `by_bal = max(pool, key=命中)` 改成 `max(rows, key=命中)`（去掉约束）
     → 它会选 0.5/top-k 1000，命中最高，但那是**句式级复读**。
   - 改成 `max(rows, key=distinct-2)`
     → 它会选 1.1/top-k 200，distinct-2 最高，但生成已经不成词。
   亲手把两个坑各踩一次，比记住结论牢得多。
5. **把 `chars_per_token` 改错会怎样？** BPC 会跟着错，但 loss 和 perplexity 不变。
   这能帮助记住每一个指标各自依赖什么假设。

## 十一、下一步可以往哪走

- **换简体语料**：同一套代码，cl100k 的利用率会高不少，生成质量也更好判断
- **用自己训练的分词器**：不用现成的，用 SentencePiece / BPE 在这套语料上训一个
- **加 KV cache**：现在生成 150 个字要做 150 次前向，每格 13 分钟全耗在这上面
  （见第九节最后一段）。加上 cache 后每步只算 1 个位置，这是投入产出比最高的一步
- **换 RoPE**：现在的位置编码是「加法」，RoPE 是「旋转」，是目前主流方案
- **量化推理**：训完的模型转成 int8 / nvfp4，用更低位宽做推理
- **训得更久**：`--max-iters 6000`。实测 train/test 两条曲线到 3000 步都还在降，
  差距稳定在 +0.21 没有扩大——这是「还能继续学」的直接证据
