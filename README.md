# transformer-from-scratch

从零手写 Transformer —— 一次完整的本地复现实验。

在不依赖任何 Transformer 库的前提下，把 `Attention Is All You Need` 里的每个模块
落成可运行、可打印张量形状、可被断言检查的代码，并在一台 12GB 显存的笔记本上
完成从注意力到中文预训练、再到模型评估的全流程。

五个脚本，核心代码约 400 行。

```
step0_attention.py    注意力：把论文里最难的方框拆成十行，逐步打印张量形状
step1_tiny_gpt.py     字符级 GPT：2.73M 参数，莎剧语料，181 秒训完
step2_seq2seq.py      补齐论文左半边：encoder + cross-attention + 正弦位置编码
step3_bpe_gpt.py      真实工程：BPE 分词器 + 中文古籍 + bf16 + 梯度累积 + 词表裁剪
step4_evaluate.py     评估：三层判据，回答"训出来的模型到底行不行"
```

---

## 一、这项实验在做什么

读论文时最容易卡住的地方是「知道每个模块叫什么，但不知道具体要写什么」。
本实验的目的就是把这句话变得具体：论文里的每一个方框，对应到哪一行代码、
输入输出张量的形状怎么变、哪些部分是论文写了但没说清、哪些是论文完全没提。

三个设计取舍：

**1. 不使用任何 Transformer 抽象。** 没有 `nn.Transformer`、没有 `transformers`、
没有 `einops`。注意力就是 `q @ k.transpose(-2, -1)`，FFN 就是两个 `nn.Linear`，
位置编码就是一行 `sin/cos` 公式。所有中间张量的形状和数值都能追到来源。

**2. 三种注意力实现为同一个类。** 论文 Figure 1 把自注意力、掩码自注意力、
交叉注意力画成三种不同样式的箭头，实际落地只差两个参数：

```
                    memory          causal
encoder 自注意力     None            False    ← 双向，能看全句
decoder 自注意力     None            True     ← 不能看未来
cross-attention     encoder 输出    False    ← Q 来自 decoder，K/V 来自 encoder
```

**3. 所有结论均为本地实测。** 下节的每个数字都由本仓库的脚本产出，可复现。

## 二、实验结果

### 2.1 各阶段训练结果

| 阶段 | 模型 | 语料 | 参数量 | 耗时 | 结果 |
|---|---|---|---|---|---|
| 1 | 字符级 GPT | tinyshakespeare 1.1MB | 2.73M | 181s | val loss **4.20 → 1.49**，ppl 4.41 |
| 2 | seq2seq 序列反转 | 程序合成 | 0.24M | 69s | 训练长度内 **100%** 准确率 |
| 3 | BPE GPT | 四大名著 2.2M 汉字 | 11.2M | 401s | val loss **7.07 → 2.70**，BPC **5.68** |
| 4 | 评估上述模型 | 同上 | — | 13min | 比字频基线好 **52.4%** |

显存峰值仅 **1.3GB**，12GB 显存远非瓶颈。真正的限制因素是语料规模与训练时长——
论文使用的 WMT14 数据集有 450 万句对、训练耗时 12 小时。

### 2.2 词表裁剪是收益最高的单项优化

分词器共 100277 个词条，语料实际只用到 **1066 个（1.1%）**。
原因是 `cl100k_base` 的中文词条几乎都是现代简体词，对繁体古籍基本退化成
字节级编码（1 个汉字 ≈ 1.47 个 token）。

处理方式是扫描语料、把出现过的 token 重新编号：

```python
uniq = np.unique(ids)                                  # 语料实际用到的 token
lut = np.full(enc.n_vocab, -1, dtype=np.int64)
lut[uniq] = np.arange(len(uniq), dtype=np.int64)        # 原编号 -> 新编号
ids = lut[ids].astype(np.uint32)
```

| | 裁剪前 | 裁剪后 |
|---|---|---|
| 输出层参数 | 38.5M | **0.41M** |
| 模型总参数 | 49.3M | **11.2M** |
| 训练速度 | 0.85 步/秒 | **7.48 步/秒（8.8×）** |
| 初始 loss | ln(100277) = 11.52 | ln(1066) = 6.97 |

表达能力无损。需要注意的是，这是封闭语料场景下的做法；工业级预训练不会裁剪得
如此激进（需保留泛化余量，且多分片语料的词表各不相同）。

### 2.3 perplexity 不能跨分词器比较，BPC 才能

这是多数教程不会提及的一点。实验中会得到两个数字：

| | 词表 | val loss | perplexity |
|---|---|---|---|
| 字符级模型 | 65 | 1.49 | **4.41** |
| BPE 模型 | 1066 | 2.70 | **14.61** |

表面上字符级模型好得多，但这个比较**不成立**。

```
perplexity = exp(平均每个 token 的交叉熵)
```

「每个 token」包含多少内容取决于分词器。字符级 1 token = 1 字符，
BPE 1 token = 0.68 字符。**切得越碎，相同内容用越多 token 表示，perplexity 天然越大**。
这不是模型变差，是度量单位变了。

唯一可跨分词器比较的是 **BPC（bits per character）**：

```
BPC = loss / ln(2) / (平均每个 token 覆盖几个字符)
```

含义是「编码一个字符需要多少比特」，与词表大小、分词方式都无关。
本实验中 BPE 模型实测 **5.68 比特/字符**。

### 2.4 与基线对比才能判断模型是否真的学到了东西

单看 loss 2.68 不说明任何问题，必须有参照物：

| 方案 | 测试段 loss | BPC | 相对"均匀瞎猜"的改进 |
|---|---|---|---|
| 均匀瞎猜（什么都不学） | 6.97 | 14.78 | 0.0% |
| 只按字频猜（一元模型） | 5.63 | 11.94 | 19.2% |
| **本实验模型** | **2.68** | **5.68** | **61.5%** |

拆成两段：

- 瞎猜 → 只知字频，拿走了 **19.2%**。这段**不需要任何"智能"**，统计词频即可。
- 字频 → 模型，又拿走 **52.4%**。这段依赖上下文，**才是注意力真正起作用的部分**。

一元模型基线计算成本极低，却能区分「学会了语言」与「只记住了字频」，
是评估中最应做、也最常被跳过的一步。

### 2.5 单一生成质量指标都会被骗，且方向相反

这是本实验除 padding 问题外最有价值的发现。实测数据：

| 配置 | 3字组命中 | distinct-2 | 最长复读 | 实际文本 |
|---|---|---|---|---|
| 真实语料（人写的，参考线） | 1.000 | 0.923 | 2.2 | — |
| 0.5 / top-k 1000 | **0.901**（第一） | 0.679 | 2.2 | **句式级复读** |
| **0.7 / top-k 50（推荐）** | 0.804 | 0.870 | 1.8 | 通顺 |
| 1.1 / top-k 200 | 0.441 | **0.970**（第一） | 1.7 | 不成词 |

两个「第一名」都是坏答案：

**「3字组命中率」被复读刷虚高。** 命中率第一的配置生成结果如下：

```
那人道：「我們是那裏來的？」那人道：「你們也不是那裏來的？」
那人道：「東土大唐朝來的。」那人道：「我們且住……
```

复读文本的 n-gram 高度重复，而重复的 n-gram 恰好都被语料覆盖，导致命中率虚高。
注意它的「最长复读」只有 2.2——**字符级无重复，是句式级在打转**，
只有 distinct-2 能捕捉到。

**「distinct-2」被乱码刷虚高。** 温度越高越不重复，因此它
**不能跨温度比较**，只能在同一个温度内比较 top-k。

正确做法是 **一个可跨温度比较的决策指标 + 一个硬约束**，缺任一项都会选错：

```python
bar_d2 = 0.85 * ref_rep["d2"]          # 门槛按真实语料自动折算，不拍脑袋
pool = [r for r in 网格 if r.d2 >= bar_d2 and r.最长复读 <= 3]
推荐 = max(pool, key=lambda r: r.命中率)   # 决策用可比的指标
```

该规则选出 `温度 0.7 / top-k 50`，生成效果：

```
卻說道：“大夫來了，你可巧討這些人來？"薛姨媽道：“這是怎么樣的．
你就說他為著呢。”寶玉道：“他那時常常見他們想的，還敢叫他呢．
```

另有两条评估工程经验：

- 极值类指标方差大。同一配置重跑，distinct-2 稳定在 ±0.02，但「最长复读」
  （12 条样本取最大值）能从 1.7 跳到 8.2。**能算均值就不要只看极值。**
- 生成是最耗时的一步（无 KV cache，每生成一个字都要重算整条前缀）。
  本实验评估一次 13 分钟，结果落盘缓存后重跑只需 **7 秒**。

### 2.6 正弦位置编码没有带来外推优势

同样 3000 步、同样任务、训练长度 1~8：

| 测试长度 | 可学习 embedding | 论文的 sin/cos |
|---|---|---|
| 4、8（训练内） | 100% | 100% |
| 10（训练外） | 79.9% | **79.9%** |
| 12（训练外） | 66.5% | **66.5%** |

**两者完全相同。** 位置向量能靠公式算出来，不等于模型会使用它——
注意力模式是训练得到的，只见过长度 ≤8 的交互，序列变长后同样失效。

次要差异：正弦编码收敛更慢（500~1000 步卡在 26.7%，可学习编码 500 步已到 84.8%）。

### 2.7 11.2M 模型的自发行为

3000 步、7 分钟、四大名著混训后，模型自行学会了三件未被显式教授的事：

1. **区分子作品。** 「卻說」提示下生成西游记人物（唐僧/行者/獅精），
   「寶玉」提示下生成红楼梦人物（襲人/寶釵/林黛玉）。
2. **跟随作品切换标点。** 红楼梦的间隔号「．」与缩进被复现，西游记/水浒则用「。」。
3. **对话格式正确。** 引号成对、`道：「」` 嵌套、换行位置。

**结论：它学到了语言的形式，尚未学到意义。** 温度 0.9 以上开始崩坏。

## 三、核心代码

注意力全部内容（`step0_attention.py`，单头版）：

```python
q, k, v = qkv(x).chunk(3, dim=-1)      # (B,T,d) -> 3×(B,T,d)
scores = q @ k.transpose(-2, -1)       # (B,T,T)  ← O(T²) 的唯一来源
att = F.softmax(scores / d**0.5, -1)   # 不缩放，点积方差随维度增大会让 softmax 饱和
out = att @ v                          # (B,T,d)
```

自监督目标（`step1_tiny_gpt.py`，论文完全未提及的部分）：

```python
x = data[i     : i + block_size    ]   # 模型看到的
y = data[i + 1 : i + block_size + 1]   # 要预测的，右移一格
```

仅这一格偏移，语料便自动变成数十万条训练样本，无需任何人工标注。

因果 mask（GPT 的核心机制）：

```python
m = torch.tril(torch.ones(T, T, dtype=torch.bool))
att = att.masked_fill(~m, float("-inf"))   # 右上角 -inf，softmax 后自动变 0
```

没有它，模型训练时能看到答案，loss 会好看得不真实，但推理时完全不可用。

## 五、踩坑清单

以下每条都是实验过程中真实遇到并修复的问题。

### 5.1 缓冲区长度必须固定（最隐蔽）

初版实现让张量长度等于当前任务的最大长度，出现了如下结果：

```
序列长度 4  -> 整句准确率 49%     <- 反常，应比长度 8 简单
序列长度 8  -> 整句准确率 100%
```

原因：同一句"长度 4"的样本，训练时后面跟着 4 个 `PAD`，**评估时一个 `PAD` 都没有**。
encoder 是双向注意力，会真正"看到"那些 PAD 位置，
attention softmax 的归一化范围一旦变化，输出表示就会漂移。

而长度 8 因两次都恰好无 PAD，侥幸得到 100%——**这种"部分正确"最容易掩盖问题**。

修法：定义 `BUF = 12` 常量，训练/评估/生成三处共用同一个张量长度。

> 论文里一句 "we pad sequences"，背后需要处理的就是这个问题，论文对此只字未提。

### 5.2 teacher forcing 与自回归必须分开评估

- `evaluate()` 喂入正确答案 → 测"每一步是否正确"
- `greedy_decode()` 把自己的输出接回去 → 测"整条序列能否生成正确"

两者可以相差 **100% vs 0%**，这是 exposure bias，不是 bug。

### 5.3 提示词字形必须与语料一致

语料是繁体，提示词写简体「却说」会直接报错——「却」从未在语料中出现，
编码后是词表外 id，用于索引 embedding 时越界。正确写法是「卻說」。

**词表裁剪后这个问题更易触发**：模型只认语料中出现过的 token。

### 5.4 先存盘，再演示

初版把「生成演示」放在「保存权重」**之前**，结果提示词字形写错抛出异常，
**七分钟训练得到的权重随之丢失**，只能重跑。演示环节应始终放在落盘之后。

### 5.5 解码语料必须整段解码，不能逐 token 解

评估时需建立"语料包含哪些字符"的集合，初版逐 token 调用 `decode`：
字节级分词下单个 token 是半个汉字的字节片段，单独解码只会得到 `�`，
真实汉字反而被判为"语料外字符"，数字全部失真（虚报 38~45）。

同理，三字组命中率的参考表必须建立在**整段语料**上：
只取 10% 建表会把命中率从 0.80 压到 0.37，系统性低估模型表现。

### 5.6 其它

- 中文 `print` 中的引号一律使用 `「」`。`print("...任何"智能"...")` 是 SyntaxError。
  修改后建议先执行 `python -c "import ast; ast.parse(open(f).read())"` 校验。
- 混合精度下 `loss / grad_accum` 这一句不能省略，否则梯度放大 4 倍，训练直接发散。
- 权重初始化使用 `std=0.02`，不要用默认的 `1/sqrt(fan_in)`，否则 logits 初始值过大。
- `ignore_index=PAD`，否则模型会把容量用于学习"预测填充符"。
- 评估时调用 `model.eval()`，结束后恢复 `was_training`，否则 dropout 会让数字抖动。
- Windows 控制台需要 `sys.stdout.reconfigure(encoding="utf-8")`。
- 长时间生成任务在前台运行会被超时终止且缓冲区输出全部丢失，建议加 `python -u` 并放到后台。

## 六、一处偏离论文的实现：pre-norm

```
论文（post-norm）   ：x = LayerNorm(x + Sublayer(x))
本仓库（pre-norm）  ：x = x + Sublayer(LayerNorm(x))
```

论文放在后面，现代实现放在前面。原因：post-norm 在层数较多时训练不稳定，
需要精细调节 warmup 才能收敛；pre-norm 使残差通路成为一条梯度"高速公路"。
主流开源大模型代码采用的都是 pre-norm。

## 十一、后续可扩展方向

- **加 KV cache**：当前生成 150 字需做 150 次前向（每次重算整条前缀），
  `step4` 评估一次 13 分钟几乎全耗在此处。加入 cache 后每步只计算 1 个位置。
  **这是投入产出比最高的一步**，也是理解大模型推理的入口。
- **换 RoPE**：当前位置编码是"加法"，RoPE 是"旋转"，为当前主流方案。
- **自训分词器**：用 SentencePiece / BPE 在本语料上训练一个，中文压缩率会显著改善。
- **量化推理**：把训练好的模型转成 int8 / nvfp4。
- **训练更久**：3000 步时 train/val 两条曲线仍在下降、差距稳定在 +0.21，
  说明仍有余量，`--max-iters 6000` 应还有明显提升。
