# transformer-from-scratch

从零手写 Transformer，在一台 **12GB 显存的笔记本**上跑到能生成中文古文。
五个脚本、约 400 行核心代码、不用任何 Transformer 库。

读完 `Attention Is All You Need` 之后最大的困惑是"具体要写什么"。这个仓库就是那个答案：
**把论文里的每一个方框，落成一行能跑、能打印形状、能被断言检查的代码。**

```
step0_attention.py    注意力：把论文里最难的方框拆成十行，逐步打印张量形状
step1_tiny_gpt.py     字符级 GPT：2.73M 参数，莎剧语料，181 秒训完
step2_seq2seq.py      补齐论文左半边：encoder + cross-attention + 正弦位置编码
step3_bpe_gpt.py      真实工程：BPE 分词器 + 中文古籍 + bf16 + 梯度累积 + 词表裁剪
step4_evaluate.py     评估：三层判据，回答"训出来的东西到底行不行"
```

---

## 为什么值得看

**1. 不依赖黑盒。** 没有 `nn.Transformer`、没有 `transformers`、没有 `einops`。
注意力就是 `q @ k.transpose(-2, -1)`，FFN 就是两个 `nn.Linear`，
位置编码就是一行 `sin/cos` 公式。每个数字都能追到来源。

**2. 三种注意力在代码里是同一个类。** 论文 Figure 1 把自注意力、掩码自注意力、
交叉注意力画成三种不同样子的箭头，落地只差两个参数：

```
                    memory          causal
encoder 自注意力     None            False    ← 双向，能看全句
decoder 自注意力     None            True     ← 不能看未来
cross-attention     encoder 输出    False    ← Q 来自 decoder，K/V 来自 encoder
```

**3. 每个结论都是这台机器上真跑出来的。** 不是"据说"、不是"论文里说"。
下面「实测结论」一节的每个数字都可以用仓库里的脚本复现。

## 实测结论（可直接引用）

### 训练结果

| 阶段 | 模型 | 语料 | 参数量 | 耗时 | 结果 |
|---|---|---|---|---|---|
| 1 | 字符级 GPT | tinyshakespeare 1.1MB | 2.73M | 181s | val loss **4.20 → 1.49**，ppl 4.41 |
| 2 | seq2seq 序列反转 | 程序合成 | 0.24M | 69s | 训练长度内 **100%** 准确率 |
| 3 | BPE GPT | 四大名著 2.2M 汉字 | 11.2M | 401s | val loss **7.07 → 2.70**，BPC **5.68** |
| 4 | 评估上述模型 | 同上 | — | 13min | 比字频基线好 **52.4%** |

显存峰值：阶段 3 只有 **1.3GB**。12GB 根本不是瓶颈——
真正的瓶颈是语料和训练时间（WMT14 有 450 万句对、论文训了 12 小时）。

### 一、词表裁剪是性价比最高的优化

分词器有 100277 个词条，语料只用到 **1066 个（1.1%）**。

因为 `cl100k_base` 的中文词条几乎都是现代简体词，对繁体古籍基本退化成字节级编码
（1 个汉字 ≈ 1.47 个 token）。做法很简单——扫一遍语料，把出现过的 token 重新编号：

```python
uniq = np.unique(ids)                                  # 语料实际用到的 token
lut = np.full(enc.n_vocab, -1, dtype=np.int64)
lut[uniq] = np.arange(len(uniq), dtype=np.int64)        # 原编号 -> 新编号
ids = lut[ids].astype(np.uint32)
```

| | 裁剪前 | 裁剪后 |
|---|---|---|
| 输出层参数 | 38.5M | **0.41M** |
| 模型总参数 | 49.3M | **11.2M** |
| 训练速度 | 0.85 步/秒 | **7.48 步/秒（8.8×）** |
| 初始 loss | ln(100277) = 11.52 | ln(1066) = 6.97 |

**表达能力无损。** 注意这是封闭语料教学场景的做法，工业预训练不会裁这么狠
（要留泛化余量，且多分片语料词表不同）。

### 二、perplexity 不能跨分词器比较，BPC 才能

这个坑几乎所有教程都不提。你会有两个数：

| | 词表 | val loss | perplexity |
|---|---|---|---|
| 字符级模型 | 65 | 1.49 | **4.41** |
| BPE 模型 | 1066 | 2.70 | **14.61** |

看起来字符级模型好得多？**完全错误。**

```
perplexity = exp(平均每个 token 的交叉熵)
```

"每个 token"是多少内容取决于分词器。字符级 1 token = 1 字符，
BPE 1 token = 0.68 字符——**切得越碎，同样内容用越多 token 表示，perplexity 天然越大**。
这不是模型变差，是尺子换了。

唯一可比的是 **BPC（bits per character）**：

```
BPC = loss / ln(2) / (平均每个 token 覆盖几个字符)
```

含义是"编码一个字符需要多少比特"，与词表大小、分词方式都无关。
本项目 BPE 模型实测 **5.68 比特/字符**。

### 三、比基线才知道模型是不是在装样子

光看 loss 2.68 说明不了任何事。得有参照物：

| 方案 | 测试段 loss | BPC | 相对"均匀瞎猜"的改进 |
|---|---|---|---|
| 均匀瞎猜（什么都不学） | 6.97 | 14.78 | 0.0% |
| 只按字频猜（一元模型） | 5.63 | 11.94 | 19.2% |
| **本项目模型** | **2.68** | **5.68** | **61.5%** |

拆成两段读：

- 瞎猜 → 只知字频，拿走了 **19.2%**。这段**不需要任何"智能"**，统计词频就行。
- 字频 → 模型，又拿走 **52.4%**。这段靠上下文，**才是注意力真正在做的事**。

> 一元模型基线便宜到可以随手算，却能把"学会了语言"和"只是记住了字频"分开。
> 它是评估里最该做、最常被跳过的一步。

### 四、任何单一生成质量指标都会被骗，而且方向相反

**这是本项目除了 padding 那个坑之外最值钱的发现。** 实测数据：

| 配置 | 3字组命中 | distinct-2 | 最长复读 | 实际文本 |
|---|---|---|---|---|
| 真实语料（人写的，参考线） | 1.000 | 0.923 | 2.2 | — |
| 0.5 / top-k 1000 | **0.901**（第一） | 0.679 | 2.2 | **句式级复读** |
| **0.7 / top-k 50（推荐）** | 0.804 | 0.870 | 1.8 | 通顺 |
| 1.1 / top-k 200 | 0.441 | **0.970**（第一） | 1.7 | 不成词 |

两个"第一名"都是坏答案：

**「3字组命中率」被复读刷虚高。** 命中率第一的配置长这样：

```
那人道：「我們是那裏來的？」那人道：「你們也不是那裏來的？」
那人道：「東土大唐朝來的。」那人道：「我們且住……
```

复读的文本 n-gram 高度重复，而重复的 n-gram 恰好都被语料覆盖 → 命中率虚高。
注意它的"最长复读"只有 2.2——**字符级没重复，是句式级在打转**，只有 distinct-2 抓得住。

**「distinct-2」被乱码刷虚高。** 温度越高越不重复，所以它
**不能跨温度比较**，只能在同一个温度内比 top-k。

正确做法是 **一个可跨温度比的决策指标 + 一个硬约束**，缺一个就会选错：

```python
bar_d2 = 0.85 * ref_rep["d2"]          # 门槛按真实语料自动折算，不拍脑袋
pool = [r for r in 网格 if r.d2 >= bar_d2 and r.最长复读 <= 3]
推荐 = max(pool, key=lambda r: r.命中率)   # 决策用可比的指标
```

这套规则选出 `温度 0.7 / top-k 50`，生成效果：

```
卻說道：“大夫來了，你可巧討這些人來？"薛姨媽道：“這是怎么樣的．
你就說他為著呢。”寶玉道：“他那時常常見他們想的，還敢叫他呢．
```

**顺带两条评估工程经验：**

- 极值类指标方差大。同一配置重跑，distinct-2 稳定在 ±0.02，但"最长复读"
  （12 条样本取最大值）能从 1.7 跳到 8.2。**能算均值就别只看极值。**
- 生成是全程最贵的一步（无 KV cache，每吐一个字重算整条前缀）。
  本项目评估一次 13 分钟，结果落盘缓存后重跑只要 **7 秒**。

### 五、正弦位置编码没有带来外推优势

同样 3000 步、同样任务、训练长度 1~8：

| 测试长度 | 可学习 embedding | 论文的 sin/cos |
|---|---|---|
| 4、8（训练内） | 100% | 100% |
| 10（训练外） | 79.9% | **79.9%** |
| 12（训练外） | 66.5% | **66.5%** |

**完全一样。** 位置向量能靠公式算出来 ≠ 模型会用——注意力模式是训练出来的，
只见过长度 ≤8 的交互，长了照样崩。
次要差异：正弦编码收敛更慢（500~1000 步卡在 26.7%，可学习编码 500 步已到 84.8%）。

### 六、11.2M 模型能学会什么

3000 步、7 分钟、四大名著混训，它自己学会了三件没人教的事：

1. **区分子作品。** 「卻說」提示下生成西游记人物（唐僧/行者/獅精），
   「寶玉」提示下生成红楼梦人物（襲人/寶釵/林黛玉）。
2. **跟着作品换标点。** 红楼梦的间隔号「．」和缩进被复现，西游记/水浒用「。」。
3. **对话格式全对。** 引号成对、`道：「」` 嵌套、换行位置。

**它学到了语言的形式，还没学到意义。** 温度 0.9 以上开始崩坏。

## 核心代码

注意力全部内容（`step0_attention.py`，单头版）：

```python
q, k, v = qkv(x).chunk(3, dim=-1)      # (B,T,d) -> 3×(B,T,d)
scores = q @ k.transpose(-2, -1)       # (B,T,T)  ← O(T²) 的唯一来源
att = F.softmax(scores / d**0.5, -1)   # 不缩放，点积方差随维度增大会让 softmax 饱和
out = att @ v                          # (B,T,d)
```

自监督目标（`step1_tiny_gpt.py`，论文完全没讲的部分）：

```python
x = data[i     : i + block_size    ]   # 模型看到的
y = data[i + 1 : i + block_size + 1]   # 要预测的，右移一格
```

就这一格偏移，语料自动变成几十万条训练样本，不需要任何人工标注。

因果 mask（GPT 的核心机制）：

```python
m = torch.tril(torch.ones(T, T, dtype=torch.bool))
att = att.masked_fill(~m, float("-inf"))   # 右上角 -inf，softmax 后自动变 0
```

没有它，模型训练时能看到答案，loss 漂亮得不像话，但推理时完全不能用。

## 踩坑清单

这部分可能是全仓库最值钱的。每条都是真踩出来的。

### 1. 缓冲区长度必须固定（最隐蔽）

第一版让张量长度 = 当前任务的最大长度，结果：

```
序列长度 4  -> 整句准确率 49%     <- 反常！应该比长度 8 简单
序列长度 8  -> 整句准确率 100%
```

原因：同一句"长度 4"的样本，训练时后面跟着 4 个 `PAD`，**评估时一个 `PAD` 都没有**。
encoder 是双向注意力，它会真的"看到"那些 PAD 位置，
attention softmax 的归一化范围一变，输出的表示就飘了。

而长度 8 因为两次都恰好无 PAD，侥幸 100%——**这种"部分正确"最容易骗过自己。**

修法：定义 `BUF = 12` 常量，训练/评估/生成三处共用同一个张量长度。

> 论文里一句 "we pad sequences"，背后真正要处理的就是这个。论文一个字没写。

### 2. teacher forcing 和自回归必须分开评估

- `evaluate()` 喂正确答案 → 测"每一步会不会"
- `greedy_decode()` 把自己的输出接回去 → 测"整条能不能生成对"

两者可以差到 **100% vs 0%**，这是 exposure bias，不是 bug。

### 3. 提示词字形必须和语料一致

语料是繁体，提示词写简体「却说」直接报错——「却」从未在语料里出现，
编码后是词表外的 id，拿去索引 embedding 就崩了。繁体是「卻說」。

**词表裁剪后这个坑更容易踩**：模型只认语料出现过的 token。

### 4. 先存盘，再演示

第一版把「生成演示」放在「保存权重」**之前**，结果提示词字形写错抛异常，
**七分钟训出来的权重跟着一起没了**。演示环节永远放在落盘之后。

### 5. 解码语料必须整段解码，不能逐 token 解

评估时想建"语料里有哪些字符"的集合，第一版逐 token `decode` →
字节级分词下单个 token 是半个汉字的字节片段，单独解码只会得到 `�`，
真汉字反被判成"语料外字符"，数字全错（虚报 38~45）。

同理，三字组命中率的参考表要建在**整段语料**上：
只取 10% 建表会把命中率从 0.80 压到 0.37，系统性冤枉模型。

### 6. 其它

- 中文 `print` 里的引号一律用 `「」`。`print("...任何"智能"...")` 是 SyntaxError，
  我在这上面中招三次。写完先 `python -c "import ast; ast.parse(open(f).read())"` 过一遍。
- 混合精度下 `loss / grad_accum` 这一句不能少，否则梯度放大 4 倍，训练直接发散。
- 权重初始化用 `std=0.02`，别用默认的 `1/sqrt(fan_in)`，否则 logits 一开始就太大。
- `ignore_index=PAD`，否则模型会花容量去学"预测填充符"。
- 评估时 `model.eval()`，用完恢复 `was_training`，否则 dropout 让数字抖动。
- Windows 控制台要 `sys.stdout.reconfigure(encoding="utf-8")`。
- 长生成任务前台跑会被超时杀掉且缓冲区输出全丢，用 `python -u` + 后台运行。

## 一个故意偏离论文的地方：pre-norm

```
论文（post-norm）   ：x = LayerNorm(x + Sublayer(x))
本仓库（pre-norm）  ：x = x + Sublayer(LayerNorm(x))
```

论文放后面，现代实现放前面。原因：post-norm 在层数多时训练不稳定，
要精细调 warmup 才能收敛；pre-norm 让残差通路变成一条梯度"高速公路"。
翻任何开源大模型的代码，看到的都是 pre-norm。

## 下一步可以往哪走

- **加 KV cache**：现在生成 150 字要做 150 次前向（每次重算整条前缀），
  `step4` 评估一次 13 分钟全耗在这。加 cache 后每步只算 1 个位置。
  **这是投入产出比最高的一步**，也是理解大模型推理的入口。
- **换 RoPE**：现在的位置编码是"加法"，RoPE 是"旋转"，目前主流方案。
- **自己训分词器**：用 SentencePiece / BPE 在这套语料上训一个，中文压缩率会好很多。
- **量化推理**：训完的模型转 int8 / nvfp4，接上 llama.cpp 那套。
- **训得更久**：3000 步时 train/val 两条曲线都还在降、差距稳定在 +0.21，
  说明还有余量，`--max-iters 6000` 应还有明显提升。
